# ProseMirror Diff — прототип

Сравнение двух версий ProseMirror-документа с подсветкой вставок, удалений и
изменений форматирования, отрисованное прямо в read-only `EditorView`.

## Запуск

```bash
npm install
npm run dev
```

Проверить диффер отдельно от UI (структурная валидность результата через
`doc.check()`):

```bash
npm run smoke
```

## Как это работает

0. **`src/markdown/fromMarkdown.ts`** — вход через Markdown: `MarkdownParser`
   из `prosemirror-markdown`, сконфигурированный поверх нашей собственной
   схемы (`markdown-it` в режиме `commonmark`, без сырого HTML). Названия
   узлов/марок 1:1 совпадают с `defaultMarkdownParser`, так что конфиг токенов
   почти дословно повторяет оригинал — просто указывает на наши node/mark
   имена. Markdown сначала целиком превращается в PM-документ, и только потом
   этот документ идёт в дифф — HTML/картинки/хардбрейки, которых нет в нашей
   схеме, тихо отбрасываются (`ignore`), а не роняют парсинг.

1. **`src/schema.ts`** — обычная PM-схема (paragraph/heading/list/blockquote/
   code_block/hr, marks strong/em/underline/strike/code/link) плюс три
   служебные, только презентационные марки: `diffInsert`, `diffDelete`,
   `diffFormat`. Блочные узлы несут необязательный атрибут `diffStatus`
   (`inserted` / `deleted` / `modified`) для подсветки всей строки.

2. **`src/diff/schemaConfig.ts`** — декларативный реестр: какие узлы схемы
   диффер считает «строками» (leaf, с инлайн-контентом или void, как
   `horizontal_rule`) и «контейнерами» (`wrap`, как blockquote, или `list`,
   как bullet_list+list_item). **`src/diff/flatten.ts`** — обобщённый движок
   поверх этого реестра: разворачивает документ в плоский список «строк» с
   сохранением пути до контейнера и собирает структуру обратно; сам он про
   конкретные имена узлов ничего не знает. Незарегистрированный тип узла не
   роняет диффер, а один раз пишет предупреждение в консоль
   (`warnUnknownNodeType`) и молча теряет содержимое такого узла в
   Diff-панели. Что именно трогать при расширении схемы — по шагам в
   [`docs/EXTENDING_SCHEMA.md`](docs/EXTENDING_SCHEMA.md).

3. **`src/diff/lcs.ts`** — обычный LCS-дифф (O(n·m)), переиспользуется и на
   уровне строк, и на уровне символов.

4. **`src/diff/inlineDiff.ts`** — посимвольный дифф внутри пары строк:
   выравнивание идёт по символам, а затем для совпавших символов отдельно
   сравнивается набор марок — если текст тот же, а форматирование другое,
   это `diffFormat` (изменение форматирования), а не delete+insert.

5. **`src/diff/diffDoc.ts`** — дифф строк, склейка соседних
   delete-run/insert-run в пары «строка отредактирована» (когда они лежат в
   одном структурном слоте), запуск inline-диффа и сборка итогового
   read-only документа через `rebuildDoc`.

6. **`src/components/ReadonlyEditor.tsx`** — тонкая обёртка над
   `prosemirror-view`: `editable: () => false`, `dispatchTransaction`
   игнорирует любые попытки редактирования.

7. **`src/components/DiffView.tsx`** / **`src/App.tsx`** — UI: селектор
   примера, легенда, статистика по диффу, сам read-only diff-блок и
   (опционально) исходные old/new версии рядом.

## Режимы UI

- **Markdown → ProseMirror** (по умолчанию) — два textarea (old/new
  Markdown), каждый на лету парсится в PM-документ и уходит в дифф; ошибка
  парсинга показывается под соответствующим textarea, не роняя страницу.
- **Готовые PM-документы** — прежний режим с примерами в виде готового PM
  JSON (`src/data/samples.ts`), полезен для демонстрации возможностей схемы,
  которые Markdown не выражает (underline, strike, произвольные PM-доки).

## Расширение схемы

Схема будет расти — при добавлении узлов/марок почти всегда нужно
обновить `src/diff/schemaConfig.ts` (и иногда ещё пару мест). Подробный
чек-лист по сценариям (новый лист, новый контейнер, новая марка, новый
атомарный инлайн-узел типа картинки, доступность из Markdown) —
в [`docs/EXTENDING_SCHEMA.md`](docs/EXTENDING_SCHEMA.md).

## Ограничения прототипа

- Список поддерживаемых узлов задаётся реестром в `src/diff/schemaConfig.ts`
  (сейчас: paragraph/heading/blockquote/code_block/horizontal_rule/
  bullet_list/ordered_list); `list_item` — один leaf-блок на элемент.
- Выравнивание внутри строки — посимвольное (не пословное), но соседние
  символы одного и того же изменения (подряд идущие delete/insert/format)
  схлопываются в один чанк — один `<del>`/`<ins>`/`<span class="diff-format">`
  на весь изменённый кусок, а не по одному на символ (см. `finishChunk` /
  `groupKey` в `diffInline`, `inlineDiff.ts`). При замене слова на совсем
  другое по составу букв всё ещё возможна ситуация, когда LCS находит
  случайное совпадение одной-двух букв в середине — тогда чанков будет
  несколько (по одному на каждый непрерывный кусок расхождения), но каждый
  из них — цельный, без раздёргивания по буквам. Настоящий word-level дифф
  (токенизация по словам до самого LCS) убрал бы и это; единственное место,
  которое пришлось бы поменять — `diffInline` в `inlineDiff.ts`.
- Изменение только атрибутов блока (например, `heading level`) распознаётся
  как удаление старой строки + вставка новой, а не как «модификация».
- Markdown-парсер не поддерживает картинки, хардбрейки, таблицы, вложенные
  списки (несколько параграфов на элемент) и произвольный HTML — то, чего
  нет в `src/schema.ts`, при парсинге молча отбрасывается.
