# ProseMirror Diff — прототип

Сравнение двух версий ProseMirror-документа с подсветкой вставок, удалений и
изменений форматирования, отрисованное прямо в read-only `EditorView`.

## Запуск

```bash
npm install
npm run dev
```

Проверить диффер отдельно от UI (структурная валидность результата через
`doc.check()`):

```bash
npm run smoke
```

Нагрузочный тест на синтетическом документе (по умолчанию ~2-3 МБ):

```bash
npm run perf -- 17000   # число абзацев; 17000 ≈ 5 МБ
```

## Как это работает

### Схема — два слоя

- **`src/schema/src/`** — портируемый пакет `@schema`: спеки узлов/марок
  (paragraph/heading/blockquote/code_block/horizontal_rule/empty_paragraph/
  list/table/custom_image_node/file_attachment, marks strong/em/strike/code/
  link), markdown-парсер (`parser`) и markdown-сериализатор (`serializer`).
  Намеренно без toDOM/parseDOM для части нод — в реальном приложении, откуда
  этот пакет взят, рендер живёт отдельно.
- **`src/schema/dom.ts`** — "доп. схема для фронта": расширяет специи из
  `src/schema/src` через `.spec.nodes.update()`/`.spec.marks.update()` (не
  трогая сам пакет) — добавляет toDOM/parseDOM для узлов, у которых их совсем
  нет, добавляет атрибут `diffStatus`+`data-diff` на все диффуемые типы,
  добавляет три презентационные марки (`diffInsert`/`diffDelete`/
  `diffFormat`). Собирает и экспортирует финальную `Schema`.
- **`src/schema/markdown.ts`** — `parseMarkdown()`/`serializeMarkdown()`:
  тонкие обёртки над `@schema`'s `parser`/`serializer` с JSON re-hydration в
  расширенную схему (ProseMirror требует точного совпадения объекта `Schema`
  для `EditorState`, а `parser`/`serializer` работают со своим экземпляром).

Подробности и грабли (dual package hazard с `"type": "module"`, почему
`attrs()` должен захватывать вообще все нужные поля узла) —
в [`docs/EXTENDING_SCHEMA.md`](docs/EXTENDING_SCHEMA.md).

### Движок диффа

1. **`src/diff/schemaConfig.ts`** — декларативный реестр: какие узлы схемы
   диффер считает «строками» (leaf — с инлайн-контентом, void, как
   `horizontal_rule`/`custom_image_node`, или `structuredText`, как `table`)
   и «контейнерами» (`wrap`, как blockquote, или `list`, как
   bullet_list+list_item). **`src/diff/flatten.ts`** — обобщённый движок
   поверх этого реестра: разворачивает документ в плоский список «строк» с
   сохранением пути до контейнера и собирает структуру обратно; сам он про
   конкретные имена узлов ничего не знает. Незарегистрированный тип узла не
   роняет диффер, а один раз пишет предупреждение в консоль
   (`warnUnknownNodeType`) и молча теряет содержимое такого узла в
   Diff-панели.

2. **`src/diff/myersDiff.ts`** — алгоритм Майерса (O(N·D), компактный
   O(D²)-трейс для бэктрека вместо снэпшота всего рабочего массива на каждом
   раунде), переиспользуется и на уровне строк, и на уровне символов, и на
   уровне строк таблицы. Заменил собой наивную O(N·M) DP-таблицу — на
   документе в несколько МБ та требовала памяти, которой физически нет.
   Корректность проверена фаззингом на десятках тысяч случайных примеров
   против brute-force DP-эталона.

3. **`src/diff/similarity.ts`** + переключатель **structural / similarity**
   в `diffDoc.ts` (`linesMatchForPairing`) — как соседние delete-run/
   insert-run схлопываются в пары «строка отредактирована»: structural — по
   точному совпадению структурной сигнатуры (path/nodeType/attrs), слепо к
   содержимому; similarity — по похожести текста (коэффициент Дайса по
   биграммам). Оба режима демонстрируются рядом в UI
   (`src/components/DiffCompare.tsx`).

4. **`src/diff/inlineDiff.ts`** — посимвольный дифф внутри пары строк:
   выравнивание идёт по символам (или по атомарным инлайн-узлам вроде
   `hard_break` — суррогат `￼` + сравнение по `node.type`+`attrs`), а
   затем для совпавших единиц отдельно сравнивается набор марок — если текст
   тот же, а форматирование другое, это `diffFormat`, а не delete+insert.

5. **`src/diff/diffDoc.ts`** — дифф строк документа, рекурсивный дифф ячеек
   таблицы (`toRenderTableLine`/`pairTableRows`/`renderTableRow` — строки
   таблицы LCS-диффятся отдельно от документа, см. §9 в
   `docs/EXTENDING_SCHEMA.md`), сборка итогового read-only документа через
   `rebuildDoc`.

6. **`src/components/ReadonlyEditor.tsx`** — тонкая обёртка над
   `prosemirror-view`: `editable: () => false`, `dispatchTransaction`
   игнорирует любые попытки редактирования.

7. **`src/components/DiffView.tsx`** / **`DiffCompare.tsx`** / **`src/App.tsx`**
   — UI: селектор примера, легенда, статистика по диффу (включая время
   выполнения), тумблер structural/similarity, кнопки генерации синтетического
   документа для нагрузочного теста, сам read-only diff-блок и (опционально)
   исходные old/new версии рядом.

## Режимы UI

- **Markdown → ProseMirror** (по умолчанию) — два textarea (old/new
  Markdown), каждый на лету парсится в PM-документ и уходит в дифф; ошибка
  парсинга показывается под соответствующим textarea, не роняя страницу.
  Поддерживает GFM-таблицы, картинки/файлы-вложения, списки, код, форматирование.
- **Готовые PM-документы** — режим с примерами в виде готового PM JSON
  (`src/data/samples.ts`) — таблицы с разными сценариями (правка ячейки,
  добавленная строка, несовпадающая форма строки) и т.д.

## Расширение схемы

Схема будет расти — при добавлении узлов/марок почти всегда нужно обновить
`src/diff/schemaConfig.ts` (и иногда ещё пару мест). Подробный чек-лист по
сценариям — в [`docs/EXTENDING_SCHEMA.md`](docs/EXTENDING_SCHEMA.md).

## Ограничения прототипа

- Список поддерживаемых узлов задаётся реестром в `src/diff/schemaConfig.ts`.
  Незарегистрированный тип узла не роняет диффер, но молча теряет содержимое
  в Diff-панели (см. `warnUnknownNodeType`).
- `list_item` — один leaf-блок на элемент; несколько параграфов или
  вложенный список внутри одного пункта не развернутся в отдельные диффуемые
  строки (см. §4 в `docs/EXTENDING_SCHEMA.md`).
- Таблицы диффятся по строкам (LCS), но не по столбцам: добавленная колонка
  выглядит как "у каждой строки форма ячеек не совпала" → каждая строка
  откатывается на delete+insert по отдельности, а не показывается как "одна
  новая колонка" (см. §9).
- Выравнивание внутри строки — посимвольное (не пословное), но соседние
  символы одного и того же изменения схлопываются в один чанк — один
  `<del>`/`<ins>`/`<span class="diff-format">` на весь изменённый кусок, а не
  по одному на символ.
